# Cirno Reclaim Hybrid｜让「冻结」真正把内存还给系统

Cirno 用 cgroup freezer 把后台应用冻住，但冻结只停 CPU 调度，进程占的物理内存一点没少。
这个模块是给 Cirno 补上「回收」那一步：把已冻结的缓存进程真正结束掉，同时让前台应用主动吐出缓存。

━━━━━━━━━━━━━━

【为什么不是杀线程】

一个应用的所有线程共享地址空间、堆、锁和 ART 运行时，单独杀「占用高的线程」基本等于让它崩。
所以这里只有两条路：

· 后台回收：只对「已冻结 + 缓存级 + 非前台 + 通过名单」的进程下手，先解冻再结束
· 前台舒缓：不杀进程，只发 trim，再把私有匿名页换出到 zram

━━━━━━━━━━━━━━

【主要功能】

· 后台回收：可用内存低、PSI 压力高、或单个冻结进程过大时触发，按 PSS 从大到小回收，多轮迭代
· 前台舒缓：对前台包所有进程发 send-trim-memory，再分多轮 MADV_PAGEOUT，日志直接给 PSS 前后对比
· 深回收：杀完仍不够时，把冻结进程的匿名页换出，不杀进程
· zram / swapfile / VM 调参：开机应用，定时回写被系统重置的参数
· 三层保活：service → watchdog → C++ daemon，心跳 + pid + 命令行三重校验，掉线自动拉起
· 限额与冷却：单轮上限、每小时上限、冻结时长、回收冷却、清页缓存冷却
· 硬保护：系统界面、桌面、输入法、电话、蓝牙、NFC、GMS、root 管理器、Cirno 本体

━━━━━━━━━━━━━━

【WebUI】

四页结构，纯静态、不联网：

· 控制台：圆环仪表、可用/Swap、累计回收与释放、守护引擎、页换出状态、立即回收 / 舒缓前台 / 扫描 / 重启、日志、自检
· 场景：保守 / 均衡 / 激进三个预设，常用 12 项 + 高级参数
· 外观：跟随系统 / 浅色 / 深色、四种强调色、纯色或图片背景、组件透明度、圆角、背景遮罩、液态玻璃底栏、性能模式
· 关于：版本、作者、反馈邮箱、一键复制诊断、写邮件

日志直接读模块日志文件，带路径和大小；「自检」会输出路径、权限、守护引擎、helper 探针、内核、SELinux。

【适合谁】

· 已经装了 Cirno / LSPosed，确认后台冻结正常
· Android 12+，Magisk / KernelSU / APatch
· 想要「后台不被杀、前台不卡顿」的平衡，而不是一键清空后台

【不适合谁】

· 没装 Cirno 的（默认只回收冻结进程，会一直空闲）
· 追求「清空所有后台」的
· 不愿意承担 root 风险的

━━━━━━━━━━━━━━

【安装】

1. 先装好 Cirno 和 LSPosed，确认能正常冻结后台
2. 在 Magisk / KernelSU / APatch 里刷入模块 zip
3. 重启
4. KernelSU 打开 WebUI；Magisk 用 action.sh 或终端

【第一次用】

· 场景页先选「均衡」，觉得回收少再切「激进」
· 想先观察：打开 dry_run 跑一轮，日志里应该是 DRY 而不是报错
· 低端机或大图背景卡顿：外观页打开「性能模式」

━━━━━━━━━━━━━━

【注意】

· 需要 root，会结束后台进程、可能换出前台页，首次请先 dry_run
· 页换出需要内核支持 pidfd_open + process_madvise，不支持会自动降级为纯 trim
· 卸载后部分 sysctl 需要重启才恢复默认
· 没有做全机型验证，遇到问题请带机型、Android / 内核版本、root 方案和日志
